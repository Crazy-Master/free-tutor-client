# Маршрут пользовательской приёмки ДЗ

Обновлено 2026-10-29: панели назначения и просмотра подключены. Технический
браузерный проход выполнен на свежих тестовых ролях; можно начинать пользовательскую
приёмку учебного цикла. Поведение автоподбора на нескольких последовательных ДЗ
и полная мобильная приёмка остаются отдельными этапами дорожной карты.

## Назначение через кабинет преподавателя

Откройте ученика в нужной дисциплине → «Сформировать ДЗ».
Для обычного ДЗ выберите «Обычное ДЗ», автоподбор 0, «Из них по выбранным
темам» 0, в дополнительных номерах укажите `2362`, затем «Назначить ДЗ ученику».
Для смешанного теста нажмите «Подготовить следующее ДЗ», выберите «Тест»,
оставьте оба количества 0, укажите `2363, 2364` и назначьте.
«Посмотреть ДЗ» → «Посмотреть состав» показывает фактически назначенные задачи.
Номера 2362–2364 — синтетические задачи для проверки, не для реальных учеников.
При потере ответа нажимайте «Повторить это назначение»: параметры и ключ
сохраняются в этой вкладке даже после обновления страницы. Не закрывайте вкладку
до получения подтверждения. Ошибка валидации позволяет исправить параметры.

## Подготовка

- API на ПК запущен, опубликованный клиент обновлён обычной перезагрузкой страницы.
- Отдельные преподаватель и НОВЫЙ тестовый ученик. Реального ученика не использовать.
- Лучше последовательно переключать роли кнопкой «Выйти». Вкладки одного браузера
  используют общую сессию; независимые роли одновременно требуют разных профилей.
- Ученик раньше не решал проверяемые задачи и не получал разрешения на решения.
  Иначе ранее выданный доступ законно останется открытым даже до сдачи нового теста.
- Синтетические QA-задачи: 2362 — число (эталон `0.5`), 2363 — последовательность
  (`00120`), 2364 — ручная. Они помечены QA и не предназначены для реальных ДЗ.
- Тестовое фото без личных данных, до 3 МБ; JPEG/PNG/WebP.

## A. Вход и подготовка преподавателя

1. Открыть /teacher без входа → форма входа, нет вечного индикатора.
2. Войти преподавателем, выбрать дисциплину → доступен кабинет и нужные ученики.
3. Открыть карточку свежего тестового ученика → нет чужого прогресса.
4. В банке открыть настройки QA-задач → режим и строка видны, ведущие нули сохранены.
   Не менять ответы реальных задач ради теста.
5. Назначить обычное ДЗ из 2362 и тест из 2363/2364.
   ЭТОТ ШАГ пока требует завершения формы преподавателя; не обходить его
   изменением JSON прогресса и не считать отсутствие формы ошибкой ученика.

## B. Обычное ДЗ ученика

6. Выйти и войти учеником → только собственные назначения.
7. Открыть 2362 → условие есть, решения ещё нет.
8. Отправить `abc` → ошибка формата, не запись неправильной попытки.
9. Отправить `9` → «Неправильно», в истории одна попытка; решения нет.
10. Отправить `0,50` → «Правильно», решение доступно; ДЗ завершено,
    открытая карточка не должна закрыться. История сохраняется после перезагрузки.

## C. Тест и ручная проверка

11. Попытаться сдать пустой тест → понятная ошибка, можно продолжать заполнение.
12. В 2363 отправить `120`, затем `00120` → правильность не показывается;
    `120` отмечен как заменённый. Решение до сдачи не открывается.
13. В 2364 отправить объяснение и фото → «Ожидает проверки», повторная работа
    до решения преподавателя недоступна. Можно открыть свою отправленную работу.
14. Сдать тест → для 2363 «Правильно», решение открыто; 2364 ожидает учителя,
    всё ДЗ ещё не завершено. Старый `120` не должен дать неправильную попытку.
15. Преподавателем вернуть 2364 на доработку с комментарием → ученик видит причину,
    может отправить исправление; старая работа и фото остаются в истории.
16. Зачесть исправление → ученик обновляет историю, видит комментарий и решение;
    всё ДЗ завершено. После перезагрузки состояние сохраняется.
17. В отдельном новом назначении проверить «Не зачтено» → одна ошибка и группа 3,
    без создания нового доступа к решению. На уже зачтённой задаче этот сценарий
    не проверять: прежний доступ за правильное решение не отзывается.

## D. Сбои и телефон

18. Выйти, войти другой ролью → чужие карточки и черновики не остаются.
19. При недоступном API → понятная ошибка и возможность повтора/входа,
    не вечная загрузка. Повтор после потери ответа не должен удваивать попытку.
20. Пройти основной путь на телефоне: читаемые поля, фото открывается,
    кнопки нажимаются, ничего не уезжает горизонтально. Отметить неудобства
    экранной клавиатуры: полноценный мобильный аудит ещё отдельный этап.

Для каждого шага: «пройдено / ошибка / не проверялось». Для ошибки прислать роль,
страницу, действие, ожидание и фактический результат, время и скриншот без паролей,
токенов и персональных данных реальных учеников.
