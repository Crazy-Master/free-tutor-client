# Ученический цикл ответов: реализация и QA

## Реализовано

- Краткий ответ для явно настроенных Number/OrderedDigits, строковый ввод без
  потери ведущих нулей, история по 50 записей с загрузкой более ранних.
- Ответы проверяет сервер, клиент не сравнивает их с эталоном и не угадывает результат.
- Для Manual/Unconfigured предлагается отправка текста/фото преподавателю.
- Согласованы ручная и автоматическая отправки: неизвестная/недоступная история
  блокирует отправку, Pending-работа блокирует автоответ, ожидающий сдачи автоответ
  блокирует ручную работу по той же задаче. Зачтённая задача закрыта для новых работ.
- Повтор после потери ответа сохраняет requestId; редактирование ввода создаёт
  новый запрос. Кнопки блокируются на время отправки/сдачи.
- Тест: результат до сдачи скрыт; замена показывает старую версию как неучитываемую;
  после сдачи история обновляется. Обычный ответ получает результат сразу.
- Прогресс обновляется без закрытия открытой карточки; разрешённое решение
  подгружается после зачёта. Ошибка обновления списка не выдаётся за потерю ответа.
- Неотправленные черновики в этом этапе не сохраняются при закрытии задачи/страницы.

## Автоматические проверки

79 клиентских тестов, TypeScript, production build; ESLint — без новых предупреждений
(3 прежних react-refresh и прежнее предупреждение о .eslintignore).
14 новых тестовых случаев покрывают строковый ввод, повтор/смену ID, блокировки,
замену тестового ответа без раскрытия результата, сдачу/открытие решения,
сохранение карточки при завершении, пагинацию, сбои истории и отменённые ответы.
Полный серверный набор — 146 тестов на отдельных PostgreSQL-базах.

## Ограничение полной приёмки

При сверке исходников обнаружено: в StudentInfoPage кнопки «Сформировать ДЗ» и
«Посмотреть ДЗ» переключают activePanel, но содержимое этих панелей отсутствует.
Поэтому браузерный проход здесь начинается с заранее созданного API-назначения,
а не с полноценного назначения в кабинете преподавателя. Не следует объявлять
пользовательский путь «назначить → решить → проверить» целиком готовым.
Подключение назначения/просмотра — ближайший шаг перед общей приёмкой.

После QA выполнен выход, оба тестовых аккаунта снова деактивированы и refresh-токены
очищены. Записи QA сохранены для аудита, не удалялись. Временная вкладка закрыта,
пользовательская вкладка не закрывалась. Сервер оставлен запущенным.
