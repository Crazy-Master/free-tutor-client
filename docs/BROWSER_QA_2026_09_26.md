# Проверка опубликованного клиента — 2026-09-26

Среда: https://free-tutor-client.vercel.app, рабочий API https://api-tutor-master.ru.
Проверки выполнялись только на специально созданных тестовых пользователях.

## Исправленная ошибка

В URL карточки находится ID пользователя, но API прогресса и разрешений ожидает ID связи «преподаватель — ученик — дисциплина». Клиент передавал первый вместо второго. При несовпадающих ID карточка/разрешения не работали.

Теперь карточка получает актуальный список учеников выбранной дисциплины, находит связь и передаёт её ID в API и обе панели. Устаревший список в хранилище не является источником ID. Добавлены обработка отсутствующей связи и регрессионные тесты.

Опубликовано в main и Cusor_AI: `ed66103`, `b0ff84d`.

## Проверено

- Браузер: вход преподавателя, выбор дисциплины, добавление тестового ученика, открытие карточки.
- Браузер: закрытое решение → выдача разрешения → перезагрузка страницы → разрешение сохранилось → отзыв разрешения.
- API от имени ученика: при разрешении задача 825 возвращает ответ и решение; после отзыва оба поля скрыты.
- Браузер: ID задачи 0 отклоняется понятным сообщением валидации.
- Автотесты клиента: 39 passed; проверка типов и production build успешны. ESLint: 0 ошибок, 3 существующих предупреждения react-refresh.

## Ограничения и следующий шаг

Проверка узкого экрана выявила горизонтальное переполнение: фактическая ширина viewport 375 CSS px, документа — 654 CSS px (при запрошенном размере 390 × 844). Временная настройка viewport сброшена. Следующая отдельная подзадача — адаптировать шапку и карточку ученика, затем повторить проверку.

Это не полный аудит мобильной версии. Интерфейс ученика для решения задач ещё не готов; получение/сокрытие ответа проверялось через API, а не через отсутствующий пользовательский сценарий. Администратор в рабочей базе не создавался. Сценарии нескольких преподавателей и правильного ответа в этой живой проверке не воспроизводились.
